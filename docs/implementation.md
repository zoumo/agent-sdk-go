# 合仓实施规格与验收票据

设计依据：用户附件 `agent-sdk-go-monorepo-design.md`（2026-10-18，Library 全文 351 行）。附件结尾是上一次设计阶段的范围，本次授权实施 A–D。当前环境未提供 `to-spec` / `to-ticket` 技能，以下采用规格、票据、验收证据的对应结构。

## 规格

一个 module `github.com/zoumo/agent-sdk-go`、一个版本、根 Go 1.26.9，由 mise 管理。无根通用客户端、嵌套 module、go.work、旧路径兼容层。两个公开原生包和两个标准库依赖的 types 包保持独立；不得相互导入。保留原始历史、许可证、NOTICE、schema、录制来源、未知数据和缺口报告。

共享范围为故事与验收测试，以及仅管理已确认关系的 `internal/lineage`。图不解析原生事件、不推断创建、不产生回答句柄。Claude 身份别名、run、去重、缓存、传输和回答状态机继续独立。每个观察实例拥有自己的图。禁止恢复 TreeRecord/TreeEvent。

## 票据 A：目录、module 与 CI 迁移

- 输入：Codex `0719539580dce97726aba7ddb56c7c6ae0c24362`，Claude `72041470958a0d9f2f8e6ff5c0086a66ef193745`。
- 目标仓库初始 main：`b1842a41a815768d9f1ba7fc22ca29843a7ad97e`；保留现有历史，不强推。
- 仅迁移目录、导入路径、构建和文档，不修改运行语义。
- 验收：新路径构建；原生 schema/inventory/录制/示例检查；离线、race、vet；Linux/macOS CI；源提交可达。

## 票据 B：共同故事与两套适配

- 根 `docs/stories/` 覆盖 US-001–US-012；各自文档记录原生映射和限制。
- 测试适配使用各自公开 API；共同约束不要求相同事件全序，不引入通用公开客户端或问答接口。
- 能力记录为支持、条件支持、不支持；源码、离线、真实证据分别记录，skip 不算通过。
- 验收：12 个故事均有测试位置和能力/证据记录；原生协议测试继续保留。

## 票据 C：实际共享关系图

- 提取 `internal/lineage`：已确认关系、未知父节点、冲突、环、祖先、深度和节点/关系资源上限。
- 两套实际观察路径均接入；原生识别、别名、run、去重、缓存、传输生命周期各自保留。
- 验收：共享规则测试、两个 SDK 完整离线/race/vet；不会从关系记录生成回答入口。

## 票据 D：消费者与发布准备

- 仓库外临时 consumer module 仅从新仓库拉取精确版本，无 replace、go.work。
- 新路径说明、发布流程、版本说明和限制齐备。
- 验收：独立消费者构建；跟踪 main 精确 SHA 的 Linux/macOS CI。
- 不创建 tag 或 release。真实 agent 测试显式关闭；既有真实子 agent 未验证状态保留。

每票完成验证后独立提交并推送 main。旧仓库只读取，不修改、删除或归档。阶段证据记入相应提交的文档与最终报告，不提交临时执行日志。
