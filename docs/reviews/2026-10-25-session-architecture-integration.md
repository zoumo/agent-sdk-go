# Codex / Claude 架构检查整合与改造提案

日期：2026-10-25。状态：合同取舍已确认；以下是未来实施提案，未修改 SDK。依据为 [Codex 独立报告](2026-10-25-codex-architecture-alignment.md)、[Claude 独立报告](2026-10-25-claude-architecture-alignment.md)及当前 harness。两份原报告保留其检查基准与证据限制，不追改成新设计的验证结果。

本次对合同和少量关键源码做只读核对，没有重新运行两份报告中的 SDK 测试或访问上游。规范集中在 harness，本报告只记录冲突整合、现状映射、实施依赖及验证计划，不成为第二份设计事实源。

## 核心判断

两套实现需要共同深化的 Module 是长期 Session：调用者学会一个 Interface，就能完成主会话输入、原生观察、真实审批、配置、中断、加载和关闭。隐藏在其内的是连接、范围、句柄、回放与资源的协调。保留原生协议差异并不要求应用承担这些协调。

Codex 当前的连接客户端、Subscription、Requests 与 LoadedThread 把正常交互拆成数个必须协调的公开对象；Claude 已有长期 Client 和单 Receive，但关系归因及去重阻挡原生交付，审批权限又只从回调取得。不能简单把 Codex 改成现有 Claude 的结构，也不能只在现有对象外增加 Session 转发壳。

目标设计见 [Session 深模块](../../harness/modules/native-session/design.md)；共同目标见 [SDK-US-001～020](../../harness/sdk/user-stories.md)。两 SDK 仍独立，不引入根通用客户端或共享回答状态机。

## 合同冲突及裁决清单

“已确定”表示 harness 既有目标已有明确要求；“本轮确认”表示采用本轮用户接受的建议。规范修订不证明实现随之改变。

| 编号 | 冲突或未定事项 | 裁决与规范位置 | 实施后果与验收 |
|---|---|---|---|
| C1 | 新目标要求接收顺序，旧交付合同允许归因等待及重排 | 已确定：已确认成员的事实立即按接收顺序接受，父级后续补充。[事件交付](../../harness/contracts/event-delivery.md) | 替换两端 pending/held 作为原生交付门卫的设计；A 未知父级、B 根、C 关系，原生顺序仍 A→B→C。 |
| C2 | graph root reachability 被当作全部成员资格；通信目标被记成父级 | 已确定：membership 与 parentage 分开。[关系合同](../../harness/contracts/lineage.md) | 兄弟通信不改父级；已知成员无需根路径。父图资源限制不得变成会话预设层数。 |
| C3 | 单入口与多订阅、独立审批渠道及所有权分散冲突 | 单入口已确定；本轮确认同连接同主身份一个所有者。[ADR-0003](../../harness/adr/0003-session-ownership.md) | 重复 Open/Load 冲突；不同身份隔离；通知、真实请求及原句柄同入口；应用自行分发。 |
| C4 | “所有已接收事件保留”与“不得混入无关事件”缺少接收范围 | 本轮确认连接接收不等于 Session 接收，未归属材料有界隔离，不补插实时流。[事件交付](../../harness/contracts/event-delivery.md) | 明确隔离数/字节/保留期及缺口；关闭前已接受的 Session 事实全部排空，不能仅保全已经进旧 ChannX 的子集。 |
| C5 | Codex 默认本地审批超时；Claude 无 handler 自动 deny | 已确定：无人回答沿原生等待，取消或终止改变原句柄状态。[通用架构](../../harness/sdk/architecture.md) | 删除 SDK 默认决策与倒计时；Call/Write 超时仍独立。审批 admission 超限显式失败，不变相自动拒绝。 |
| C6 | 实体/UUID 去重抑制原生事实；未知 run ID 被排序解释 | 已确定：原生事实保留，协议依据不足不解释 newest/stale。[关系合同](../../harness/contracts/lineage.md) | 去除事实流 seen/terminal suppression；保留 SDK 公告幂等与重复请求单次权限保护。 |
| C7 | Load 独立回放流与长期单入口冲突；Done 含义混用 | 本轮确认单入口允许历史与实时交错；加载状态独立。异步历史 (removed Load design) | 加载前普通输入拒绝，真实回答、中断和关闭可用；配置在 pending 时明确拒绝；历史生产者有界，不能另建增长 FIFO。 |
| C8 | Claude initialize 成功但身份未知即可旧 Load 成功；Codex resume 响应 ID 未直接校验 | 本轮确认原生恢复身份确认是成功前提。异步历史 (removed Load design) | Codex 校验实际 resume 响应身份；Claude 先查无执行确认机制，若不可得保留能力缺口，不用 prompt 或请求身份充当证据。 |
| C9 | 旧接口兼容是否需要保留另一套运行模型 | 本轮确认允许破坏性迁移，仅允许无独立队列/权限/所有权的薄适配。[ADR-0003](../../harness/adr/0003-session-ownership.md) | 集中更新示例、消费者和迁移说明；旧回调不能成为第二消费者。 |
| C10 | 动态队列“超限可见”被理解为必定能在 OOM 前报错 | 已确定：可用内存是边界，无崩溃/OOM 交付承诺。[事件交付](../../harness/contracts/event-delivery.md) | 不加静默丢弃或固定队列策略；历史工作集有界不代表总 backlog 有界。 |

与真正冲突分开的事项：结构输入支持范围、配置生效时机、列表查询覆盖、合法历史元数据分类都需要固定版本能力映射。不能从它们尚未实现推导原生不支持，也不能为推进计划先把未知写成支持。Codex 活跃历史拒绝及非原子分页是既有范围限制；本轮不承诺活跃执行的无损 Load。

旧 US-001～013 是场景编号，新 SDK-US-001～020 是能力目标，两者不互为别名。US-011 的新观察者历史关系 seed 不是自动重连，也不是显式 Load 全路径。US-013 有合同但当前共享 storyIDs 只列到 US-012，不能宣称已覆盖。

## 从现状到深 Module 的处理

| 对象或机制 | 处理 | Codex 影响 | Claude 影响 |
|---|---|---|---|
| 原生 types / codec / Raw | 保留并补必要协议类型 | 请求顶层原文也要保留；新增查询及设置协议类型须走生成与来源校验 | 保留未知数据；结构输入新增写路径，不从输出解码支持推导输入支持 |
| 传输、writer、dispatch 证据 | 保留，缩小公开协调负担 | 连接内部为 Session 路由；显式共享连接仍有独立拥有者 | 保留本地进程、writer 与有界回收；无需通用传输插件框架 |
| Session 所有者 | 新增或深化 | 替换 StartThread + Subscribe + Requests 的正常使用路径 | 以现有 Client 的长期交互核心深化，无须为命名而叠加一层 |
| 观察关系 | 简化 | 成员集合独立于父图，移除任意 completed collab receiver→sender 父边 | 取消 tree 对消息放行/去重的控制；未知 run 保持原样 |
| FIFO | 保留机械实现，改变归属 | 从每个公开 subscription 转为每 Session 一个消费入口 | 沿用一个 backlog，避免再加回调或历史队列 |
| 回答权限 | 保留权威状态，替换交付 | reverse request 同流交付；保留原生 approve/deny 选项与问答结构 | permissionState 同流交付；补有依据的原生扩展；移除默认 deny |
| Load | 保留证据机制，替换协调与所有权 | LoadedThread 不再独立拥有后续交互必须依赖的 attachment | 不以 initialize-only 宣布成功；历史/live 不要求两个消费者 |
| 子 Agent 查询与配置 | 新增正式操作 | native ancestor/page/source/archive 与 settings 操作 | 独立文件记录发现与动态配置；字段及语义按版本核验 |

迁移资源选项时须逐项处理旧值：旧合同规定 Codex 4096 nodes / depth 32、Claude MaxNodes 默认 4096（最大 65536）及独立父图计数；本轮删除的是它们作为成员模型前提的规范，不是修改当前代码默认值。旧 EventQueue / EventBuffer 已忽略、control/permission admission 独立等行为也必须在未来迁移说明中交代，不能通过修改文档声称旧选项已删除。

父图中自环、环路、冲突、别名合并及事务回滚仍有价值。迁移不能因不再要求完整树而删除这些校验。去重账本删除也不等于取消真实重复请求防护、帧大小或权限 admission 限制。

## Seam、依赖及测试安排

| 依赖类别 | 本项目落点 | Seam 的安排 |
|---|---|---|
| 进程内计算 | codec、FIFO、父级校验、历史投影 | 直接验证公开值及机械合同；不为每项新增 Adapter 接口。 |
| 本地可替代存储 | Claude transcript、sidecar、目录发现 | 私有存储 seam，以临时目录构造真实文件形状、变更与访问失败；不暴露存储协调给调用方。 |
| 真正外部原生运行时 | Codex app-server、Claude CLI | 注入必要私有 I/O/进程启动 seam；生产原生对端与固定协议的离线对端是实际 Adapter。离线通过不证明模型行为。 |
| 显式共享连接 | 多 Session 复用已有连接 | 所有者注入与 session registration 是实际变项；用公开操作验证关闭隔离和回答唯一性。 |

没有需要本项目自建远程服务才能深化的 Module，不新增自己的控制服务或远程传输协议。新故事以 Session Interface 为测试面，验证返回值、可读事件、真实对端收到的原生输入/答案和资源释放；不靠读私有树状态证明用户已经看到事件。

替换与新合同相反的排序、去重、默认 deny、额外审批超时断言，同时保留原有边界案例及故障、并发、未知字段和回收覆盖。不是简单删除旧单测；每个被删除的有效保证应有新公开路径或独立机械测试承接，符合项目[测试规则](../../harness/testing.md)。

## 有依赖顺序的改造提案

每阶段都是未来实现工作。本文没有授权真实 Agent、模型、新录制、提交或推送。

### P0：合同、能力清单与证据调查

本轮完成合同取舍及目标文档同步。实施前将两份报告的 20 项映射整理为对应版本的检查清单：对外操作、必需参数/内容类型、成功含义、支持状态、原生依据、计划验证和未验证范围各列独立。

优先调查 Claude 的无执行恢复身份确认；配置的动态参数、生效范围；两端列举的版本/存储覆盖；Claude 非链元数据分类。固定已有基线，不自动升级。声明文件、另一版本官方实现、当前 CLI 行为分别记录，不混用。

退出条件：已确定合同无相反验收要求；未知能力标为未知；Load 身份调查即使发现不可实现，也不阻止非 Load 阶段推进。未确认结构输入不能被笼统计为完整支持。

### P1：建立 Session 所有权与最小原生闭环

依赖 P0 的已确认合同。保留 codec、writer、transport、dispatch 及清理核心，先形成 Open→主输入→原生结果→再次输入→Close 的公开路径。注册同连接同主身份唯一所有者；启动期间事件必须可保留，不能在暴露 Session 后才安装观察。

Codex 固定主 thread 目标、连接共享和 Session attachment 所有权；Claude 深化已有长期 Client。两端明确终止、清理及排空，未知提交结果不重发。连接级扩展保留原生表达，但不得偷偷建立第二所有者。

退出条件：重复拥有冲突、多 Session 隔离、本地等待取消、多次输入、原生失败继续交互、终止后排空，以及共享连接与自有进程关闭的公开验收通过。

### P2：替换事实交付与观察门卫

依赖 P1。建立成员证据与可选父级，移除 held/pending 的归因放行、native UUID/terminal suppression 和无依据 run 排序。一个 Session FIFO 接受全部已归属事实；未知连接材料集中隔离，数/字节/保留期及缺口可验证。

退出条件：A→B→C 顺序、同 ID 不同 Raw 与完全相同重复、无父级成员、兄弟通信、长会话不受额外根消息 seen 账本寿命限制、隔离到期/超限、关闭和断线排空通过。限制拒绝关系时仍保全已接收原生事实。

### P3：真实请求进入单入口

依赖 P2。连接保有原生权限 registry，Session 只交付相同句柄。移除 Codex 默认 RequestTimeout 过期与 Claude 默认 deny / 核心回调池；普通 RPC 超时保持独立。按原始请求提供 approve/deny、问答和已支持扩展，原生协议错误回复不能冒充用户拒绝。

退出条件：延迟无人回答、持续读流、原生取消即时失效、回答/取消/Close 竞争、发送未知不重试、历史/ParseEvent/隔离材料不授予权限、重复请求不增加有效回答次数。使用可控时钟验证超过旧本地超时，不执行长时间真实等待。

### P4a：原生输入与配置

依赖 P1/P3 和对应 P0 证据。主输入支持原生结构，文本便捷调用复用同一路径。明确每种内容的接入范围；共同命名 SetModel / SetThinking 保留原生参数、确认强度和不支持错误，不定义跨 Agent 档位或隐式 start/steer 选择。

退出条件：文本与已接入内容的公开发送保真、执行期间输入原生接受/拒绝、配置成功/拒绝/不支持/结果未知、请求值与观察值分离；无隐式中断、重建或递归修改子 Agent。

### P4b：独立子 Agent 列举

依赖 P1 的固定身份和 P0 查询证据；可与 P4a 并行，不依赖 P3 的回答交付。Codex 补正式查询类型及祖先分页；Claude 独立发现本次观察之前的原生记录，保留目录、sidecar 和身份的证据限制。

退出条件：多页/空页/不推进游标/访问失败/部分结果/归档与来源条件/未知父级/已结束成员均明确；对端观测到零 resume、start、subscribe 和历史回放。列表结果不自动改变观察范围，不以缓存冒充查询。

### P5：Load 接入同一 Session

依赖 P2/P3 及 P0 的恢复确认调查，不依赖 P4b。保留历史快照、原文、主链、分页、变化检测及有界读取，迁移 attachment 与客户端所有权。Load 返回可消费的 Session；历史与实时交错，加载状态独立。普通输入和配置 pending 时明确拒绝，真实回答、中断、关闭继续运行。

Codex 单独校验 resume response identity；Claude 仅在存在经过取证的无执行确认方式时实现成功路径，否则提供明确能力缺口及失败，不改写成功定义。继续保留稳定主历史限制；实时源变化使快照失效时明确失败，不承诺活跃执行无损恢复。合法非链元数据可扩展分类，但不放松主链、身份及源变化校验。

退出条件：错身份、身份未确认、历史/live 交错、慢回放期间真实审批与中断、成功边界、部分回放后失败、源变化、取消与关闭、权限不复活，以及加载成功后取消 startup context 不停止 Session。Load 失败不能通过薄适配恢复为可输入成功状态。

### P6：迁移消费者与交付验证

依赖 P4a/P4b/P5。更新例子、消费者、类型能力清单与迁移说明，集中移除需要旧双流/回调/多订阅的运行模型。薄适配只能委托同一 Session，不能复制队列、恢复附着或有效权限。建立新 20 项公共故事映射，旧故事保留其编号意义。

退出条件：mise 固定工具链上的离线、race、vet、生成/协议 inventory、录制哈希及脱敏、依赖隔离验证按实际改动通过。独立消费者最终须在已授权推送后获取精确 revision、无 replace/go.work；尚未推送时保持该检查待验证，不为完成计划擅自推送。真实多输入、配置效果、子 Agent 与 Load 验证另行授权，合成及既有录制结果不升级为真实兼容性。

依赖简图：`P0 → P1 → P2 → P3 → P5`；`P1 + P3 + 对应证据 → P4a`；`P1 + 查询证据 → P4b`；`P4a + P4b + P5 → P6`。各阶段合成回归随工作实施，不能把所有验证推迟到 P6。
