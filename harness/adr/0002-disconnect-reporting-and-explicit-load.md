# 断线报告与显式 Load

SDK 以长期 Session 控制和原生事件交付为目标。远程连接断开后，原生执行可能继续，但重新连接、恢复订阅、处理待审批请求和补齐事件具有不同的原生条件。当前阶段不将这些行为组合为 SDK 自动恢复能力。

## 决定

- 断线后，SDK 不主动重连，将断线错误报告给调用方，由调用方决定是否以及如何重新建立交互。断线本身不证明原生执行已经停止。
- SDK 不保证重新连接后能补齐断线期间的全部历史数据或原始事件，也不承诺恢复前后的事件流无缝连续。
- 调用方需要恢复会话并读取历史时，可以显式使用已有的 `Load` 语义：先 resume 同一个原生会话，再回放该会话完整保留的主对话历史所能表达的事件。以 [异步历史加载](../contracts/async-history.md) 和 [原生历史事件](../contracts/history-events.md) 的范围及完成合同为准。
- 调用方结合自己已接收、已保存的事件判断哪些内容重复、哪些内容缺失，以及是否继续交互。SDK 不自动计算或填补断线区间。
- `Load` 回放不等于重建原始实时事件序列；不保证恢复未保留的 token 增量、进度通知或全部子 Agent 历史，也不会将历史审批转换为可回答的实时请求。无法从保留历史确认的缺口仍然未知。

## 范围

这是当前阶段采用的边界，后续可以通过新的 ADR 修订。自动重连、同一 SDK Session 对象跨连接延续、订阅恢复及审批句柄恢复的设计暂时搁置；本决定取代 [ADR-0001](0001-native-session-contract.md) 中关于远程恢复的暂定合同，不影响其中其他已确认的 Session 设计。

本 ADR 记录设计决定，不声明 SDK 实现或真实运行兼容性已经完成验证。
