# Session 单一所有权与 Load 交付

## 决定

同一连接上的同一原生主会话只允许一个 Session 拥有正常事件消费及其请求的回答权限。重复打开或加载明确失败。应用负责展示、日志等用途的分发；连接级原生扩展不创建第二份回答权限，也不绕过已建立的 Session 所有权。

连接接收与 Session 接收分别定义。不能确认属于某 Session 的原始事件进入有数量、字节及保留期限制的连接级隔离区，报告归属缺口，不交付为该 Session 的成员事件。隔离材料作为诊断读取，不能回答其中请求。后续确认成员时，不将旧材料补插进实时流，也不静默宣称覆盖完整。明确超限或到期的诊断与材料保留范围必须可见。

Load 期间历史投影、实时事件、真实交互请求及加载边界共用 Session 的一个消费入口。实时事件保持接收顺序，历史保持回放顺序；两者允许交错，不承诺历史全部先于实时。完成前拒绝普通输入，但真实请求回答、中断和关闭仍可用。加载完成独立于交互终止与事件排空。

Load 成功必须有恢复同一原生身份的确认，以及声明范围内保留主历史的完整回放。指定身份、磁盘身份与初始化成功不能替代原生恢复确认。无法取得确认时报告证据不足，不宣布成功；不得通过额外提示词、模型执行或新会话替代确认。

迁移以共同合同为目标，允许破坏性变更。旧接口只能通过不增加队列、回答权限或资源所有者的薄适配保留；不长期维护旧订阅、回调审批和独立历史流的第二套运行模型。

## 取舍

单一所有权把事件、权限及清理的协调留在 Session 内，代价是调用方必须迁移依赖独立订阅的用法。隔离未知归属避免污染会话，代价是这些早期材料不能承诺在实时流中补回。历史与实时交错使审批和控制不受历史慢消费阻塞，代价是应用按来源展示，不能把消费顺序解释为原始对话时间线。

严格的恢复确认可能使部分原生版本无法完成 Load；该能力缺口必须保留，不能降低成功定义。
