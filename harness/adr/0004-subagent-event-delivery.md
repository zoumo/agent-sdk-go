# 子 Agent 输出与 Session 事件交付

## 决定

默认保留各 Agent 的输出行为，不由 SDK 主动强制关闭子 Agent 输出。SDK 继续交付当前能够确认属于 Session 观察范围的子事件，保留可用来源身份和原生内容，由使用者决定如何展示、保存或使用。默认行为兼容现状；不以默认强制隔离子事件来降低消费复杂度，也不将两套原生协议包装成同一种协议。

本决定只记录架构，不修改实现，也不声明下面的可选扩展已经提供。成员证据、未知归属及单一所有权继续遵循 [ADR-0003](0003-session-ownership.md)和[事件交付合同](../contracts/event-delivery.md)。

## 三层边界

| 层次 | 职责与边界 |
| --- | --- |
| Agent 输出设置 | 原生运行时决定在连接或父 CLI 流中输出哪些子内容。SDK 显式设置原生选项属于 SDK 配置行为，不能称为原生默认。 |
| SDK Receive 交付 | SDK 按原生归属证据接收并交付事件；消费方选择怎样处理。观察范围与完整父图分开，不因未知直接父级拒绝已确认属于 Session 的事实。 |
| 内部结果回父 | 原生编排通过工具返回、任务状态及后续完成通知向父 Agent 提供结果；它不依赖应用读取 Receive 后再把子事件转交给父 Agent。 |

三层分别讨论，不以“原生转发”概括全部行为。SDK 接收到某个子事件不证明父 Agent 已消费结果，根结果也不证明全部后台任务完成。SDK 观察不保证后台结果立即唤醒父 Agent，不保证成功、失败和取消有等价结果。无人处理的真实审批可能阻止任务完成。

## 可选扩展方向（尚未实现）

未来可以在 Session 启动或显式 resume 的配置中提供子详细事件过滤选项；默认继续兼容当前交付。参数名称、具体 API、配置生效时机及逐类事件判定尚待后续设计确认，本 ADR 不规定公开签名，也不安排实现。

如推进此扩展，设计边界如下：

- 过滤仅作用于已确认来自子 Agent 的详细 text、thinking 和 tool 进度的 SDK 交付，不联动 Agent 输出设置，不修改内部结果回父。
- 保留父 Agent 的原生工具结果，包括代表子任务结果的父工具结果；保留关系、完成和失败通知及真实审批请求。一个 envelope 混有详细内容与必要事实时，具体保留规则须另行确认，不能整包丢弃必要事实。
- unknown 来源不能猜为 child 后删除；先按现有归属规则处理，保持归属与覆盖缺口可见。过滤不能成为扩大成员范围或补投早期未知事件的理由。
- 审批只有一个 controller，通过其原始有效句柄回答；observer 和 history 只提供观察，不产生回答权。过滤不转移权限，也不自动批准或拒绝。

保留详细事件使消费者可以自行裁剪展示，代价是消费与存储量可能较大。未来可选过滤可以降低交付量，但会减少详细可见性，需要明确其覆盖边界。用 Agent 输出开关代替 SDK 过滤会改变源头可观察数据；默认强制隔离则破坏现有使用方式，因此均不作为默认策略。

## 历史与 live 的边界

历史查询与 live 观察分别定义。读取历史不建立订阅、恢复执行或审批权限；重新附着不得伪装成纯查询。Codex 远端重新附着所用的原生 resume 具有副作用，不能假定存在纯 `thread/subscribe`。Claude 父 CLI 流的本地分流不等于独立子历史查询或远端子流订阅。

子历史支持需要独立的原生能力与覆盖证据；主会话历史支持不能外推为子历史支持。可选过滤也不承诺历史回补或完整原始事件回放。

## 非目标

本决定不引入统一生产 Client、强制同构的事件协议、新订阅或 resume 实现，不改变当前代码，也不实现历史查询。后续开发仍按项目既定的 spec、ticket 和独立 implement 流程进行；本次仅记录 ADR，不创建实施 ticket。
