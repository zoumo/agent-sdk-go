# US-014 独立发现会话与查询保存的内容

- 用户目标：无需创建 Session，发现保存的会话、读取 metadata，按原生分页或有界选择方式查看保存的内容。
- 场景输入：默认/显式 scope、多个页与空页、metadata 与内容、unknown 数据、原生拒绝和取消；已有同身份 Session 时穿插真实 live 通知。
- 共同验收：通过原生公开查询 API 保留身份、可用字段、unknown、顺序和调用方所有权，明确查询后端、范围、资源及一致性限制；有效空与失败可辨识。原生无 cursor 或 total 时不伪造；不能把 preview 当完整消息或记录存在当 running。
- 操作边界：查询不创建/恢复/订阅/提交，不注入 Receive、不建立成员关系和回答权限；已有 Session 的 live 通知照常交付。对端屏障和请求 trace 证明查询与交互隔离。
- 覆盖边界：metadata、保存的内容与原始事件日志分开表达，不承诺完整日志或跨页原子快照。主会话内容不等于子 Agent 历史或独立订阅。

- 组合验收：两端原生 adapter 在同一共同目标下完成发现 → metadata → 保存内容。Codex 保留 opaque cursor、summary/full 差异和显式页尾；Claude 在压缩与并行工具恢复后按可见消息切片，并分别检查 metadata 的采样覆盖与消息失败。后续页和有效空不得替代错误或 partial。

Claude 的具体原生场景见[消息](claude-session-messages.md)和[metadata](claude-session-metadata.md)。

具体合同见[独立历史查询](../history-query.md)，共同目标见[用户故事](../../sdk/user-stories.md)。

## independent-child-content（Claude 原生子场景）

独立 list → 选择 agentID → 读取 child messages 使用[子能力 H1–H5](child-capabilities.md)。此处对应 SDK-US-008/019，不以主消息压缩/并行恢复或 Session.ListSubagents 冒充实现；Codex 继续原生 thread 查询，不新增统一 child history。
