# agent-mock Go 模块

## 语言无关的模块契约

agent-mock 提供录制代理与 Agent mock，通过进程命令和版本化录制数据供任意语言调用。
Go Module 与包归属见[仓库架构](../../architecture.md)和[代码布局](../../architecture.md#layout-code-layout-standards)。
工具实现不导入官方 SDK、Python 或本仓库生产 SDK，不依赖 story/case 编号或 fixture 布局。
编译后的可执行文件不依赖 Git checkout，也不需要调用方安装 Go 编译器。

第一版只支持 stdio，覆盖 Codex、Claude 的 JSONL 消息协议。
不提供 HTTP、SSE、WebSocket 或进程内拦截，也不预先公开多传输插件 Interface。
stdio 是传输方式，JSONL 是第一版支持的分帧格式；不能把它当作任意二进制协议支持。

[外部 story 录制工具](#story-官方-sdk-仿真测试) 使用相应 Agent 的官方 SDK 执行 story 并录制 case。
官方 SDK 的语言只决定驱动语言，不决定代理或 mock 的实现语言。
场景解释、输入和审批策略、case 验收、SDK 依赖安装、脱敏与发布均归调用方。

## Interface 与 Seam

| 操作 | 调用方提供 | 模块负责并返回 |
| --- | --- | --- |
| 录制代理 | 真实 Agent 的可执行文件、参数、工作目录、环境、输出位置及显式限制 | 代理 stdio，保存双向消息和 stderr，报告采集状态、退出与清理结果 |
| Agent mock | 录制数据、明确的协议标识及显式限制 | 在 stdio 上扮演协议对端，报告匹配、完整消费和结束状态 |

外部 Seam 是 SDK 可替换的子进程通信入口。官方 SDK 接入层把真实 Agent 的启动入口
替换为录制代理；被测 SDK 则连接 mock。无法替换进程通信入口的 SDK 不在第一版承诺范围内。

stdout 只承载原生协议。工具诊断使用 stderr 或独立报告；采集到的真实 Agent stderr
单独保存，不混入协议或冒充代理诊断。调用方不需要管理内部读写线程、匹配状态或进程回收。
调用方提供启动配置，模块管理自己启动的进程；认证发现、配置复制和场景环境准备归调用方。

## 实现与协议 Adapter

录制实现共用 stdio JSONL 转发和存储逻辑。只解释分帧、方向和传输结束，不读取 hook、
工具、审批或子 Agent 字段来控制采集。不同 Agent 的启动参数由外部接入层提供。

mock 在内部协议 Seam 使用 Codex、Claude Adapter。Adapter 识别必要的消息分类、
请求与响应关联、允许的 ID 重绑定及客户端匹配规则；通用实现管理消费顺序、I/O 和清理。
不复制官方 SDK 的完整消息类型体系，不建立跨 Agent 的统一审批或 turn 状态机。
不支持的协议明确拒绝，不从未知 provider 猜测为某个现有协议。

Adapter 是内部扩展位置，不要求普通调用方传入一组匹配回调。
新增 Agent 使用相同 stdio JSONL 时复用录制实现，并按需要增加协议 Adapter 与外部驱动。
两个已有协议提供实际变化依据；第一版不引入动态插件加载或任意传输框架。

## 职责与三条链路

| 链路 | 发起方与协议对端 | 证据范围 |
| --- | --- | --- |
| 真实录制 | 官方 SDK 驱动 → Go 录制代理 → 真实 Agent | 选定版本和场景中的实际协议交互 |
| 可选样本校验 | 官方 SDK 驱动 → Go mock | 保存流程是否可重现，原生回执是否一致 |
| Go SDK 验收 | 本仓库 Go SDK → Go mock | 被测 SDK 对这些交互的处理是否满足断言 |

直接启动 mock 不需要官方 SDK，官方 SDK 校验也不是 Go SDK 验收的前置步骤。
采集完整、mock 匹配、case 通过是不同结论。case 和 story 的判定由外部工具负责。

## 录制与进程生命周期

录制代理只在调用方明确启动录制时执行真实 Agent。并行转发两个方向，正确处理背压、
半关闭、客户端 EOF、原生退出和取消。客户端结束输入后仍需排空 Agent 输出，不能直接截断。
取消时清理自有进程及管道，保存已经取得的数据并明确标记结束原因和不完整状态。

JSONL 按完整行分帧，不按一次 read 的字节块分帧。分片读取必须正确重组，不能依赖
默认扫描器的小行长度限制。非法 JSON、未完成帧、I/O 错误和清理失败不能记为完整采集。
新录制不覆盖旧数据。时间、字节等资源限制由调用方显式配置，命中限制必须保留失败证据。
合法的新消息类型和未知业务字段不因用例未预期而被过滤。

## 数据格式与存储

录制产物包含版本化的双向协议数据、独立 stderr、传输结果与文件哈希。
记录传输格式、代理版本、原生执行身份、退出状态和清理结果；不保存完整环境中的凭据。
官方 SDK 版本、story/case 和驱动快照由外部证据包关联，不能成为通用 mock 的必需输入。

JSONL 数据沿用 `agent-mock-jsonl` v1 的帧语义：`ordinal`、`direction`、`channel`、
`epoch`、`elapsedMs` 与 `wire`。方向为 `c2s` 或 `s2c`，第一版单进程 epoch 为 1。
`wire` 使用原始 JSON 内容，不从 SDK 对象或自定义业务结构体重建；保留未知字段、
键顺序和数字字面量。消息行尾可归一化，不宣称保留操作系统读写分块或逐字节行尾。

`ordinal` 表示代理观察顺序，不推断额外跨方向因果；时间用于诊断，不承诺精确时序重现。
不完整数据必须带有失败状态。读取支持的录制封装时保留原始数据、来源和哈希；
这不表示支持旧版 story 计划或驱动。

## 严格离线回放

1. 校验录制版本、完整性及协议适配能力；不读取认证，不探测或启动真实 Agent。
2. 按保存的交互顺序读取客户端请求、发送服务端原帧，客户端请求是相应输出的屏障。
3. 比较完整客户端消息；只按协议 Adapter 的明确规则重绑定原生关联 ID。
   原始录制不修改，输出只改动必要的关联字段，不能任意忽略业务字段或重新序列化整条消息。
4. 意外请求、内容不匹配、提前 EOF、未消费帧和等待超时均明确失败。
5. 只有完整消费并满足客户端结束条件，才报告成功；诊断须能定位到录制帧。

mock 重现录制路径中的交互，不推理新 prompt，不执行工具，不自动重建文件或历史副作用。
第一版不搜索其他录制分支，也不重新调度任意并发交互；合法但不同于所选记录的交互可明确拒绝。
精确竞态和故障测试使用显式合成数据，与真实来源分开标注。
超出解析或资源能力时明确失败，不能删帧、放宽匹配或回落到真实 Agent。

## 测试与依赖

模块测试与调用方穿过同一个 Interface，覆盖双向转发、分片与大消息、原始 JSON 保真、
双向请求 ID 关联、错误匹配、EOF、取消、stderr、非零退出、背压和进程清理。
用本地合成进程完成录制到 mock 的闭环；模块测试不依赖生产 SDK、官方 SDK、账号或真实 Agent。
可执行文件验证在源码 checkout 外运行，证明运行时不依赖源码目录。

SDK 测试通过 fixture 与进程 Adapter 调用模块，依赖与代码归属遵循上述仓库规范。

<a id="story-官方-sdk-仿真测试"></a>

## 官方 SDK 仿真测试

`tools/record-user-story/` 按官方 SDK 支持选择驱动语言，经 agent-mock 进程执行
下述流程。story/case 目录与验收映射位于 `tests/recording/`。

<a id="story-录制生命周期"></a>

### 录制生命周期

下表是外部 story 工具的操作，不是 agent-mock 的 Interface。工具通过进程 Seam 调用录制代理或 mock。

| 操作 | 输入 | 输出与执行边界 |
| --- | --- | --- |
| catalog | provider、用例选择 | 解析后的场景；不读取认证、不安装 SDK、不调用模型 |
| prepare | CLI、模型、源连接配置、场景和可选采集限制 | 新私有数据集、计划、驱动与配置快照；只查询版本，不调用模型 |
| record | 已准备的数据集 | 使用保存的驱动执行真实交互，写入协议、stderr、报告与 manifest |
| replay | 已录制数据集与明确指定的 mock | 校验来源、运行保存流程、比较结果并取得完整消费回执 |

prepare 使用程序临时目录，在 macOS 上解析目录的真实路径；省略输出路径时创建唯一目录。
显式输出必须是临时目录内的新目录，并位于 Git 外。每个用例独立 HOME、config、project、tmp
和 raw。初始文件是新建合成材料，不扫描原有项目或历史会话。

准备器只选择连接、模型和认证所需配置；保留调用方 PATH，以支持原生启动器与 hook。
不复制调用方完整环境，不改写源配置。私有目录与文件以限制访问的权限创建。

准备完成后，计划、场景、输入、初始文件和驱动源码构成该次尝试的身份。
执行前检查身份与原始文件的一致性。改变流程或驱动后准备新数据集，不修改旧快照来复用旧身份。
record 是显式真实执行入口；默认测试和 CI 不调用它，用户明确调用的 CI 录制不因 CI 环境而拒绝。

代理在原生进程边界记录双向 JSON，SDK 回执另存。输入按场景执行：普通输入等待原生结果后
发送下一条；执行中补充输入或中断由真实进度屏障触发。缺少屏障时不补发输入、不改为顺序执行，
也不为凑齐证据自动重跑模型。活动结束后终止、回收自己拥有的进程并记录清理结果。

已有尝试保留并跳过。再次录制使用新准备的目录；失败记录不覆盖、不重置。

<a id="story-场景配置"></a>

### 场景配置

Story/case 的身份、归属和验收规则见[用户故事](../../sdk/validation-cases.md#stories-sdk-用户故事)及[case 目录](../../sdk/validation-cases.md)，原生差异见[适配说明](../../sdk/validation-cases.md#native-用户故事的原生适配说明)。本节只规定录制配置与执行。

版本化 JSON 以 story 为容器，包含 `id`、完整用户目标、验收条件和 `cases` 数组。
每个 case 的 `id` 是独立 case ID，`storyId` 与容器 ID 一致；大小写、重复 ID、悬空归属和绑定错配均须拒绝。
每个 case 显式声明目标、前置条件、输入、预期结果及范围；provider 绑定按独立 case ID 定位。采集批次、日期、版本和尝试结果写入元数据。
Case 声明 `implementation=implemented/planned`；provider 路由声明 `live-selected-path/planned/unsupported`。声明目标不代表驱动或验收已实现。
只有具有实际适配器及有效真实流程的 case 才能执行。planned 与 unsupported 须给出原因，不执行替代提示词、其他 case 或专项测试。

命令用 `--stories` 选择稳定 story ID，以 `--cases` 选择独立 case ID。选 story 时展开其全部 case，
两种选择同时存在时取交集；不明确的 case 选择不能静默回落。流程按 case 执行，私有录制输出按 `<story-id>/<case-id>/` 隔离。
驱动通过显式 profile 选择原生操作，不根据 story ID 或 case ID 的数字推断行为。

通用 case 配置包括初始文件、命名输入、有序步骤、预期交互、缺证据行为和限制字段；
provider 绑定描述 prompt 差异、请求名称、答案、配置、能力缺口和公开验收入口。
目录索引显式枚举 story，case 集由容器声明；schema、story、case、绑定及驱动一起冻结，不从运行时臆造缺少的 case。

支持的语义操作是 `session.open`、`configuration.apply`、`input.submit`、`event.wait`、
`execution.interrupt` 和 `session.close`。顺序流程可以包含多组输入与结果，不设固定两输入上限；
进度流程包含一个屏障后的一次补充输入或中断。配置不包含可执行脚本、表达式或任意 shell 代码。
不支持的操作、错误引用、越出项目的初始文件路径和驱动步骤错误属于流程错误。

| 流程组 | 驱动行为与证据 |
| --- | --- |
| continuation / structured-input | 同一会话依次提交输入并等待结果，保留原生输入结构 |
| fixture-tools | 在合成项目中执行工具请求，工具返回与任务终态分别保存 |
| active-input | 进度屏障后追加一次输入，分别记录接受、拒绝或仅写入的原生结果 |
| approval / deferred-approval / questions | 处理原始请求；审批拒绝、等待期间事件交付和问答分别判定 |
| configuration / configuration-timing | 保存配置请求、回执与后续执行顺序，不把确认冒充所有生效时机 |
| interrupt | 在进度屏障后中断并保存原生终态，不以中断确认代替完成 |
| children / background-children | 根据原生子身份、读取与完成记录判定；后台用例需要根先结束、子后完成的证据 |
| stored-children / history | 独立读取明确来源的记录，不启动或恢复任务，不把保存内容当完整事件日志 |
| session-close | 显式关闭拥有的会话、检查进程清理和后续交互拒绝，不以普通输入结果代替关闭 |

真实模型的文字、分块、工具选择、执行耗时及子任务拓扑不保证确定。
原生进度只表示观察到了进度，不保证随后动作早于执行完成；精确竞态使用合成测试。
人工故障、背压、安全边界与竞态归属[代码集成测试](../../testing.md#测试层级与自动化边界)。

场景、schema、绑定和实际语言的驱动一起快照并校验哈希。修改已支持的 prompt 或步骤后重新准备即可；
增加动作类型或原生能力需要适配器实现。流程轨迹保存步骤、输入序号和原生动作结果，
与协议中的时间、文本和 token 用量分开。

<a id="story-录制限制"></a>

### 录制限制

此处约束 story 驱动与采集流程。通用代理只执行调用方指定的传输限制，
不解析审批、hook 或子任务语义；相关观察与判定由驱动或录制后的分析完成。

原则是完整保存正常执行，不因样本与预期不同而拒绝录制。

| 条件 | 处理 |
| --- | --- |
| CLI 或 SDK 版本不同于安装默认值 | 记录实际版本，不设置版本白名单 |
| hook、子任务或额外合法事件出现 | 原样捕获和转发，记录可观察活动，不因此中断 |
| 工具重复、路径或内容变化、问答选项及请求顺序差异 | 保存真实交互，可形成用例 gap，不自动变成采集错误 |
| 原生工具及扩展能力 | 不为凑用例而关闭 shell、hook、插件、memory 或子任务 |
| 普通命令、文件和 Claude 工具审批 | 原生回调允许请求；拒绝写入用例保留其预定拒绝动作 |
| 合成 fixture 回调 | 在新合成项目中读取或写入；不承担任意文件系统工具的通用实现 |
| 活动时间、传输时间、协议或 stderr 字节数、帧数、费用、原生轮数 | 录制器默认不设置固定上限 |
| 显式采集限制 | `capturePolicy.timeoutSeconds`、`protocolBytes`、`stderrBytes`；默认零表示禁用，非零时按该次计划执行 |
| 输入数量 | 由已保存流程决定，不额外施加固定两输入上限 |
| 原生 CLI/SDK 自身的限制与错误 | 保留实际行为；录制器不承诺绕过原生权限或执行能力 |

移除录制限制不改变原生协议，也不把拒绝写入、中断、普通输入或查询互相替换。
未知回调方法若无正确协议实现，属于驱动能力错误；不能编造回答来继续执行。

目录归属、初始文件一致性、计划和驱动身份、原生可执行文件哈希以及正确步骤仍须核对。
这些检查用于避免覆盖数据、混入旧材料或错误标注来源。API、协议、进程、文件系统和清理错误
仍使采集失败；原始诊断保留。操作系统资源耗尽也属于系统错误，默认无限额不构成资源或费用保证。

<a id="story-数据格式与存储"></a>

### 数据格式与存储

每个 case 的一次采集保存一份原始材料，派生 fixture 和 mock 场景不能替代原始来源。
新计划与报告分别保存 `storyId`、`caseId`；原有计划和原始报告保持冻结身份，不就地改写。

| 文件或目录 | 含义 |
| --- | --- |
| `plan.json` | provider、实际 CLI 版本与可执行文件哈希、准备时 SDK 身份、源码身份、路径、输入、场景及采集限制 |
| `driver/` | 保存的实际语言驱动源码、依赖身份、JSON 场景、schema 和绑定 |
| `attempt.started` / `native.started` | 用例尝试与原生启动账本，保留失败尝试 |
| `raw/raw.jsonl` | 双向原生 JSON 帧，核心录制数据 |
| `raw/stderr.raw` | 原生进程标准错误输出，与协议分开保存 |
| `raw/transport.json` | 帧数、字节数、结束原因及进程清理结果；hook/子活动统计属于外部分析报告 |
| `report.json` | 采集状态、用例结果、实际 SDK 身份、计数、原生回执、步骤轨迹和 gap |
| `manifest.json` | plan、驱动、原始文件及选定保存内容的 SHA-256、版本来源、扫描与覆盖信息 |
| 私有诊断文件 | API、驱动、进程或系统错误的原始分类与详情 |

协议数据遵循 [agent-mock 数据合同](#数据格式与存储)。上表描述本仓库 case
证据包的布局；story/case 身份、SDK 版本、驱动快照与验收报告由外部工具管理，
不是通用 agent-mock 读取录制时的必需输入。外部 manifest 将这些证据与代理产物的哈希关联。

原始数据位于 Git 外，不因执行成功自动入库、脱敏或发布。认证和连接配置副本在尝试结束后清理；
不发布完整 HOME/config。已知凭据扫描单独标记输出，命中不阻断采集，也不改变正常执行的状态。
扫描通过只表示未命中该检查范围，不证明任意内容均可公开。

数据目录归属见[代码布局](../../architecture.md#layout-simulation-data-and-integration-fixtures)。
不维护历史录制兼容层；合成结果不能包装成仿真回执。

新仿真数据入库前须独立审核来源与发布范围。公开 fixture 从真实样本派生，保留来源、转换说明、文件哈希、必要 ID 关系及遗漏边界。
移除秘密与归一化路径、随机 ID、时间戳是不同目的；不要求仅为“脱敏”而替换所有 ID 或时间。
不得把合成故障、适配后的客户端请求或 SDK 回执标记为未经修改的真实原生帧。

<a id="story-结果与错误"></a>

### 结果与错误

采集是否完成、用例是否通过、故事是否验收、样本是否重现是四个独立结论。

| 层次 | 状态与含义 |
| --- | --- |
| 采集 `captureStatus` | `complete`：流程与传输正常结束；`failed`：实际执行或清理错误；`not-executed`：未执行真实采集 |
| 用例 `status` / `branchStatus` | `passed`：范围内证据齐全；`untriggered`：必要行为缺失或不符合预期；`failed`：实际执行错误 |
| 执行路由 | `live-selected-path` 仅表示可执行；`planned`、`unsupported` 不执行、不产生通过证据 |
| 回放验证 | `passed`、`expected-untriggered-reproduced`、`expected-failure-reproduced` 或 `failed` |

缺少工具、问题、屏障、子身份、读取或后续完成等范围内证据，仍计为 gap，不能移到范围外以取得通过。
`captureStatus=complete` 可以同时对应 `status=untriggered`；命令返回执行成功并继续后续用例。
未被预期流程处理的 API、协议或系统错误返回非零，保留失败。预定的审批拒绝、原生补充输入拒绝
和具有明确取消终态的中断按各自流程解释，不把合法负面结果直接伪装成成功生成。

用例通过只证明已冻结的范围。story 验收遵循[用户故事规则](../../sdk/validation-cases.md#stories-sdk-用户故事)；
汇总须区分采集、协议自回放、官方 SDK 回放与 Go SDK 验收，不跨证据层抵扣。

<a id="story-严格离线回放"></a>

### 严格离线回放

选择官方 SDK 样本校验时：

1. 校验原始文件、保存的驱动、场景与依赖身份，不读取账号或启动真实 Agent。
2. 将保存的驱动接入 agent-mock，使用相应语言的官方 SDK 执行同一流程。
3. 取得 [严格 mock 回放](#严格离线回放) 的完整消费回执。
4. 比较 SDK 回执、输入/结果/请求计数、场景哈希、语义轨迹、用例范围、gap、限制和结果。
   SDK 身份记录实际运行版本；CLI 身份取自原录制，不探测回放机器上的 CLI。
5. 写入独立验证结果，先归档旧验证输出，不覆盖原始报告。

原 `untriggered` 只能重现为未触发；原失败需要相同计数、回执、诊断和完整消费，
不能因错误再次发生就声称用例通过。wire 匹配但流程或用例范围变化，同样不是成功重现。

Go fixture Adapter 只负责读取数据、启动 mock 与 SDK 断言，不实现第二套协议匹配。
测试控制或消费通知走独立管道或明确启用的测试通道，不写入真实录制、不冒充原生协议。
Go SDK 验收通过公开 Interface 执行，不安装官方 SDK 或其语言运行时。
若官方 SDK 与 Go SDK 的合法初始化能力或标记不同，只允许明确、可核对的派生适配，
记录适配来源，保留未改动的服务端原帧；不能任意忽略客户端差异。

<a id="story-版本责任与证据"></a>

### 版本责任与证据

每份录制记录实际 CLI 版本、可执行文件哈希、官方 SDK 包名与运行版本、驱动/场景快照和仓库源码身份。
准备与运行的 SDK 版本不同不作为版本白名单错误；报告记录实际运行版本。
回放依赖已保存身份和实际使用的 SDK 版本，不以“能够解析”推断其他版本兼容。

结论只对这组版本、原始字节和选定场景负责。计划、原始字节、版本与失败报告不重新标注；
工具只执行当前格式的冻结计划。普通设计编辑和离线测试不授权额外模型调用。
