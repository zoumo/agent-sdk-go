# 原生 Session 深模块设计

## 调用者与职责

应用需要打开或显式加载一个长期主会话，持续消费原生事实，随时提交输入、回答请求及控制执行，最后释放自己拥有的资源。Session Module 隐藏连接初始化、身份固定、事件分流、请求关联、加载阶段与清理的协调。调用方无需拼装订阅、独立审批回调及历史读取循环。

行为目标来自[通用架构](../../sdk/architecture.md)和[共同故事](../../sdk/user-stories.md)。本页规定项目内的逻辑 Module 与 Interface，不要求每一项成为一个包或公开接口。两个原生 SDK 独立实现；一致的操作概念不建立根通用客户端或跨原生协议的回答状态机。

## 对外 Interface

以下命名表达操作概念，不固定 Go 签名。参数、返回原生事实及错误详情分别保留各接入方类型。

| 操作 | 调用者获得的行为及必须知道的限制 |
|---|---|
| Open / Load | 返回一个可消费的 Session；固定主身份。Load 异步返回不表示恢复或回放成功。重复拥有同连接、同主身份明确失败。 |
| Receive | 唯一消费入口：原生事件、真实请求及原句柄、SDK 观察证据和加载边界；本地等待取消不结束 Session。 |
| Submit | 普通输入固定发送给主会话；保留原生结构和调度，不以本地 Busy 状态决定 start、steer 或排队。写入、原生接受与结果分别表达。 |
| SetModel / SetThinking | 参数为原生类型；创建与动态修改分开。已知不支持明确拒绝；接受不冒充已生效，不模拟配置继承。 |
| ListSubagents | 独立查询原生记录，返回原生身份、可用父级、元数据、分页及覆盖证据；不恢复、不订阅、不回放。 |
| Interrupt | 显式原生控制；允许原生执行选择器，不根据最后收到的子事件选择目标。确认不保证全部任务停止。 |
| Close / 终止观察 | 失效本 Session 权限，结束交互并释放所拥有资源；终止原因与清理结果可观察，已接收事件仍可排空。显式放弃消费才允许丢弃 backlog。 |
| 加载状态 | 独立报告 pending、成功或失败以及恢复证据；成功不表示 Session 终止，也不表示应用已经读完所有事件。 |

回答句柄属于真实 IncomingRequest 的 Interface：批准、拒绝、原生答案、支持的扩展和有效状态；与原生 RPC 错误回复区分。纯编解码、历史投影和隔离诊断不能创建句柄。原生请求及未知 envelope 字段完整保留在运行时交付值中；运行时权限不序列化进原生 types。

## 内部 Module 与状态所有权

| Module | 隐藏的复杂度与唯一拥有状态 | Seam 与依赖 |
|---|---|---|
| 原生协议 | 编解码、未知字段与变体、原始数据和固定版本语义 | 纯计算；types 生产依赖仅标准库。 |
| 原生交互 | 读写、请求关联、已发送或结果未知、连接故障、自有进程或 socket 回收 | 原生 I/O 的私有 seam；生产传输和离线对端是实际 Adapter。控制处理不依赖 Receive。 |
| Session | 主身份、唯一 FIFO、会话范围注册、事件与请求交付、加载协调、交互终止 | 外部 seam 是上表的 Interface；内部组合原生交互和记录读取。 |
| 请求权限 | 原 request ID、交互身份、有效性、取消与单次回答 | 由原生交互持有权威 registry；Session 交付同一句柄，关闭按所属 Session 失效；观察范围重叠不产生第二份回答权。 |
| 观察证据 | 成员集合、可选父级、已验证别名、覆盖缺口 | 原生 Adapter 解释证据；纯父级校验可用 internal/lineage，不能决定全部成员资格。 |
| 原生记录读取 | 主链选择、分页、快照校验、子记录发现、访问和资源限制 | 本地文件和原生查询分别使用必要的私有 seam；不拥有恢复或回答权限。 |

这些职责可在同一个原生 SDK 内组合，不为单个函数建立通用插件框架。共享机械 Module 不认识原生协议、Session 身份或权限。连接拥有 Session 注册及未归属隔离材料；Session 拥有自己的交付状态。外部显式共享连接时，关闭一个 Session 不关闭其他 Session 或整个连接。自有进程的 Session 则承担进程回收。

删除 Session Module 会使初始化、范围、审批、回放和关闭的协调重新分散到每个调用者，因此它承担实际 Depth。将每个原生 RPC 包成公开转发方法而仍让调用者协调这些步骤，不满足此设计。

## 顺序、状态与资源

实时事实沿“接收 → 归属判断 → Session FIFO → Receive”交付。确认属于会话但父级未知的事实立即接收；父级后续补充不移动已交付事实。尚未确认成员的连接事实按[隔离合同](../../contracts/event-delivery.md)处理。原生重复事实保留，SDK 关系公告可以避免重复，原生重复请求仍须保护单次权限。

Load 沿“验证来源 → 恢复确认 → 有界读取并投影 → 完整性检查 → 成功或失败”执行。实时 reader 同期工作，权限撤销立即生效；回放与实时进入同一个 FIFO，保留各自局部顺序。加载状态、交互状态、原生执行状态及清理状态分别表达，不建立总 Busy/Idle。

FIFO 以可用内存为限，不承诺 OOM 或进程崩溃后交付。历史生产者有界，不预载全部 payload；统一 FIFO 允许慢消费积压，因此“读取有界”不表示 Session 总内存有界。隔离、记录读取、请求和观察索引有各自显式限制。资源错误保留已接收 Session 事实；不通过静默丢弃恢复成功。

## 验收与测试 seam

| 初始条件与输入 | 对外可观察结果 |
|---|---|
| 同连接、同主身份重复 Open/Load | 第二个明确冲突，不产生第二消费者或回答权限；不同身份互相隔离。 |
| 已知成员 A 无父级，随后根 B，再收到父级证据 C | A、B、C 的原生相对顺序不变；父级后来补充。 |
| 未归属 X，另一个 Session 的 Y，后确认 X 成员 | 当前流不混入 X/Y；隔离诊断保留已声明范围并报告缺口；X 旧材料不回填。 |
| 同原生实体 ID、不同 Raw 或完全相同的两次到达 | 两次原生事实均保留；不能因此生成两份可回答权限。 |
| 请求到达后延迟回答，同时到达撤销或关闭 | 请求随流交付；控制处理不等消费；句柄回答时按同一权威状态校验。无人处理不自动决定。 |
| 慢历史回放期间实时请求、取消、中断和结果到达 | 同一入口可交错；真实回答和中断可用，普通输入在加载成功前拒绝；历史没有活权限。 |
| 指定身份与恢复响应不符，或只有初始化确认 | 不交付历史为成功恢复后的回放，不宣布加载成功，不执行额外模型输入。 |
| 历史已经部分交付后游标、文件或来源校验失败 | 明确加载失败并清理；已交付部分不被描述为完整；不能继续普通输入。 |
| Close 或连接故障，消费者暂停 | 权限失效、控制唤醒、资源清理不等消费；排空全部已接收事件后取得结束原因。 |
| ListSubagents 遇到分页、访问失败或旧记录 | 覆盖完整性明确；不产生 resume/start/subscribe 或审批回答，不把旧记录当运行证据。 |

采用公开 Interface 验证上述行为；必要的私有 seam 只控制原生对端、存储、时钟和故障。原生进程与外部运行时属于真实外部依赖，离线 Adapter 必须依据固定原生协议；不能用测试自创语义证明兼容。原生编解码、写入歧义、并发权限及快照完整性回归仍单独保留。替换只断言旧组织方式的测试，不叠加另一套长期故事框架，遵循[测试规则](../../testing.md)。
