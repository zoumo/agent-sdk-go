# 编码原则

本页适用于所有语言实现。
语言规范、框架和布局遵循项目约定。

- 清晰：名称表达含义，代码说明动作和必要原因。
- 简单：优先标准工具，避免无需求的机制和抽象层。
- 简洁：使用语言惯用写法，注释不重复代码。
- 可维护：明确假设与约束，命名可预测，减少依赖。
- 一致：遵循已有模式，局部调整保持整体清晰。
- 避免重复：复用相同逻辑，抽象须解决实际复杂性。

代码须便于正确修改，避免炫技。
性能优化须有实际需求。
风格调整须避免加重已有缺陷。
