# 测试与验收原则

## 验证边界

优先通过公开接口的集成测试和端到端场景验证合同。
模块设计维护具体场景，测试数量不代表覆盖程度。
离线测试验证确定性合同，不能替代真实系统验收。
默认测试不调用真实模型。
真实 Agent 或模型验收须显式执行。
替身和故障注入不能证明原生行为已通过验证。

## 环境与资源

真实验收须明确产物、配置、认证和环境。
前置条件缺失或场景为空时，报告未执行。
测试使用自有临时资源，保留个人及其他任务数据。
认证通过外部配置提供，日志和证据移除秘密。

失败时也须尝试释放己方资源，并核对结果。
完成与释放条件遵循被测组件合同。
命令启动、请求接纳或终止不等于完成或释放。

## 结果声明

结果须绑定源码、产物、环境和实际执行的场景。
源码在运行期间变化时，说明结果适用范围。
保留必要的失败证据。

结果分为通过、失败和未验证。
禁止将未执行的场景报告为通过。
筛选执行只证明选中的场景。
局部通过不代表全部场景通过。
