# 原生 SDK 通用架构

## 目标与范围

SDK 为应用提供长期 Session 控制和原生事件透传。所有接入方以同一套[共同用户故事](user-stories.md)验收，不以复制官方 SDK 的全部接口为目标。

共同能力不要求原生协议、参数类型、事件结构或调度结果相同。统一常用控制操作，保留原生表达及证据；不能准确映射的差异须明确暴露。原生限制是能力缺口，不能通过删去共同故事或静默降级掩盖。

## 术语

| 术语 | 含义与边界 |
|---|---|
| Session | 可持续接受输入并交付多次执行事件的原生会话上下文。一次执行返回结果不结束 Session。 |
| 主会话 | 本次打开或恢复的原生会话，是普通输入的默认目标。 |
| 输入提交 | 按原生操作提交输入。成功的含义由该操作的证据决定，不自动表示已接受或执行完成。 |
| 执行结果 | 原生提供的一次执行结果或完成边界，不证明 Session 空闲或全部后台工作停止。 |
| 观察成员 | 原生证据确认其事件属于当前 Session 观察范围的 Agent。成员关系不要求已知直接父级。 |
| 回答句柄 | 绑定实际原生交互请求、携带其回答权限与有效状态的操作对象。 |
| 观察缺口 | 原生证据、订阅能力或资源边界导致无法确认观察完整的区间或范围。 |
| Load | 显式恢复同一个原生会话，再回放其完整保留的主对话历史所能表达的事件。 |

不强制建立通用 Turn 对象，也不为缺少原生依据的执行周期合成身份、开始事件或完整归属。原生提供的执行身份与边界应保留。

## 职责划分

以下是逻辑职责，不要求实现为特定的层、包或接口继承体系。

| 职责 | 负责内容 |
|---|---|
| 原生协议适配 | 解析、编码、原生身份、控制操作及未知数据保留；解释版本固定的原生语义。 |
| Session 与资源管理 | 建立交互、持续事件交付、中断、关闭、错误报告及所拥有资源的释放。 |
| 观察关联 | 基于原生证据确定成员、保留可用父级、自动建立必要订阅并报告缺口。 |
| 共同控制 | 统一审批以及模型、思考配置的操作概念，保留原生参数与回答权限。 |
| 应用策略 | 输入时机、结果展示、事件分发、审批决定、应用超时、任务完成判断及断线后的处理。 |

观察关系不授予执行、回答或配置权限。共用操作界面不要求共用原生协议状态机。

## Session、输入与配置

Session 的事件流跨多次输入和执行持续存续。执行结果、Session 交互结束和事件已读尽是不同事实。

普通输入发送给主会话。SDK 不依据最近收到的子 Agent 事件改写输入目标；直接向子 Agent 发消息需要独立、显式的目标与能力合同。

文本是共同基础输入。已支持的图片、附件和结构化输入保留原生类型，不将其隐式改写为提示词。SDK 沿用原生输入调度，不仅因存在前台执行就统一拒绝，也不自行建立排队、追加或抢占策略。

模型选择和修改采用共同操作概念与命名，参数使用原生模型标识。区分创建时选择与运行中修改。思考配置同样统一操作概念，参数保留原生类型；不定义未经共同需求与证据支持的跨 Agent 档位或预算映射。

配置操作只承诺原生能够确认的结果、生效时机和作用范围。设置已接受不等于当前执行已切换；请求值不能冒充已观察到的当前值。SDK 不通过延迟调度、中断、重建 Session 或遍历子 Agent 来模拟修改。

原生配置继承与修改范围保持原状。已知不支持的操作或参数须明确拒绝，不能忽略或改成其他操作。无法提前确认时，保留原生拒绝与不确定性；无需额外建立通用实时能力发现服务。

## 事件与生命周期证据

每个 Session 提供一个有序事件消费入口，由应用向自身的展示、日志等用途分发。保留接收顺序，不声称不同 Agent 的全局发生顺序。独立订阅者的缓冲、进度和回放不属于此合同。

保留原生事件类型、未知字段或变体、可用来源身份及原始数据。不能补造原生没有提供的执行证据。必要的关联、交互句柄及 SDK 连接状态须与原生事实区分。

原生状态照常暴露；不合成跨全部 Agent 的 Busy/Idle 总状态。应用依据目标判断何时完成。原生标识相同不自动表示事件重复；保留各自原生重复与关联规则。

消费变慢时，保持已接收事件的完整、有序交付，不静默丢弃或合并。控制回复的处理不等待应用消费事件。SDK 必须说明资源边界与超限结果，不能承诺无限资源或进程崩溃后仍可交付。

## 子 Agent 观察与列举

默认观察覆盖原生证据确认属于 Session 的直接或间接子 Agent，不预设层数。保留已知父级；缺失父级时不补挂到根节点，不以完整树为事件交付前提。

原生已经转发的事件直接接收；需要额外订阅时自动建立可用的观察。自动订阅不启动、恢复或重跑任务，不批准权限，也不保证补回订阅前遗漏的事件。根执行完成后，仍继续观察关联子 Agent。覆盖受限须报告缺口，不能据此认定不可见的 Agent 已停止。

提供显式列举当前 Session 子 Agent 的能力，使用原生查询或保留记录发现，不能仅返回当前事件流中的缓存成员。返回原生身份与可用元数据，保留父级、运行状态及查询覆盖的未知部分。列表记录不证明仍在运行或已建立订阅。

列表查询本身不触发恢复、历史回放或订阅。分页、存储访问及原生版本限制须明确；部分结果不能表示为完整列表。

## 审批与交互问答

审批采用统一操作界面，覆盖请求接收、批准、拒绝及取消或失效的观察。保留原生详情；修改输入、限定授权范围等扩展只在原始请求支持时提供。

请求通过 Session 事件流携带回答句柄交付。应用可继续消费事件，稍后回答；合同不要求另一套独立回调交付机制。回答绑定原请求与有效性约束，只允许一次有效回答。结果未知时不能自动重试。

交互问答通过其原始请求和答案结构回答，不以普通输入代替。工具调用、问题文本或关系记录本身不能创建回答权限。

无人回答时沿用原生等待、超时和取消规则。SDK 不自动批准、拒绝或设置额外通用审批超时；应用决定自身策略。原生取消、超时及交互终止须反映到句柄有效性。

重新建立连接不自动恢复旧句柄的权限；历史回放不产生可回答的实时请求。审批句柄跨连接恢复不属于当前合同。

## 取消、故障与关闭

取消一次本地事件等待只结束该等待，不中断执行或关闭 Session；应用可再次读取。输入或回答可能已经发出时，保留结果未知，不把超时表示为未执行，也不自动重发。

中断通过原生操作影响执行；返回成功不自动证明执行已停止或副作用已回滚。关闭结束 SDK 的交互与观察，并释放所拥有资源。关闭自己拥有的进程与关闭外部连接可能产生不同执行结果，不能统一承诺递归停止所有 Agent。

原生执行或工具失败作为原生事件交付，不单独导致 Session 终止。传输、协议等 SDK 故障须报告错误及当前交互是否终止，不能伪装为正常执行结果。

关闭或终止故障后，允许排空 SDK 已接收的事件，再观察流结束及原因。资源释放不等待应用读完事件。交互终止、进程退出和资源清理完成须按各自证据表达。

## 断线与 Load

断线后报告错误，SDK 不主动重连，由应用决定后续交互。连接断开不证明原生执行已经停止。SDK 不保证重新接入后补齐断线期间的全部事件或无缝延续原事件流。

需要恢复与历史时，应用显式使用 Load：先确认恢复同一个原生会话，再回放其完整保留的主对话历史所能表达的事件。历史须可与实时证据区分；回放未完成或失败不能表示为加载完整。

Load 不重建原始实时事件序列，不保证未保留的 token 增量、进度通知或全部子 Agent 历史。应用结合自己保存的内容判断重复与缺失；SDK 不计算或填补断线区间，也不因回放而重执行工具或回答历史请求。

自动重连、同一对象跨连接续接、订阅与句柄恢复、应用重启后的持久恢复均不属于当前合同。修改这些边界须先修订设计与共同验收目标。
