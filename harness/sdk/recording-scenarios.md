# 确定性录制与回放场景

[共同用户故事](user-stories.md)的录制单元是版本化场景。每个录制用例只验证一个有明确边界的场景。场景固定输入、初始文件、原生配置、步骤、事件屏障、交互答案、预算与验收分支。US 是需求索引，一个 US 可以关联多个独立用例，不要求一次录制覆盖全部验收条件。一个目标的成功、拒绝、取消和故障分支分别验收。原生补充条件遵循[原生故事](native-stories.md)。

## 确定性的范围

真实运行固定应用行为及判定规则，不保证模型文字、分块、工具选择、执行耗时或子任务拓扑相同。原生执行提供事实；prompt 不替代屏障、权限或资源限制。未出现所需请求或屏障时，记录未触发，不追加提示、自动重试或伪造原生成功。

回放使用保存的驱动源码和场景，严格核对原生双向协议、请求关联及完整 EOF。仅原生协议明确允许的 envelope ID 可以关联重绑定。回放成功表示保留路径得到复现，不代表目标全部通过。

## 场景合同

场景定义是独立于实现语言的 JSON 配置，以 JSON Schema 描述数据合同。通用场景包含版本、目标编号、流程组、执行方式、命名输入、初始文件、有序语义步骤、预期交互、资源上限与缺证据行为。每个用例有独立身份、明确的验证范围和范围外事项；这些内容参与计划及场景哈希。场景索引枚举可用定义；定义不由执行器代码生成。

Agent 绑定配置单独描述原生 prompt 变体、文件差异、请求映射、答案、配置、能力缺口与验收入口。未显式覆盖的值沿用通用场景。通用事件使用 execution.progress、execution.result 等语义名称，不引用 Python 类或原生 RPC。原生适配器解释这些事件，绑定配置不自动实现新 Agent。

执行器加载、校验并解释配置。第一版语义步骤包括 session.open、configuration.apply、input.submit、event.wait、execution.interrupt 和 session.close；支持顺序输入/结果，以及一个进度屏障后的一次补充输入或中断。不支持的操作、顺序或引用在启动前拒绝。配置不包含可执行脚本、表达式或任意 shell 命令。

修改 prompt 或重组已支持步骤，只需修改配置并重新准备。增加新的动作类型或原生能力仍需要执行器实现。Python 是一个消费者，其他语言可以基于同一配置和 schema 实现自己的执行器。公开目录不需要安装官方 SDK、读取用户配置或调用 CLI。

准备时保存完整解析场景与规范化 JSON 的 SHA256，原始配置、绑定、schema 和驱动源码同时冻结。manifest 绑定 plan 文件及驱动、原始录制、保存内容的哈希。修改 prompt、文件、流程或驱动需要新数据集；历史数据沿用原始身份和快照。

流程控制器只管理录制动作，不持有原生回答权限，不成为 SDK 运行时依赖。原生适配负责配置、事件解释、句柄、答案和错误。原生协议及模型参数不跨 provider 转换。

## 流程组

| 流程组 | 驱动流程与屏障 | 目标 |
|---|---|---|
| continuation / structured-input | 提交固定输入，等待原生结果后再提交下一条；保留结构化输入类型 | 001、002 |
| fixture-tools | 固定数字文件；实际读取请求后写入固定结果；核对请求顺序，工具结束不代替任务结果 | 004 |
| active-input | 第一条输入 → 原生进度屏障 → 仅一次补充输入 → 保存接受、拒绝或仅写入证据 → 观察结果 | 003 |
| approval / deferred-approval / questions | 等原始请求，按固定策略和顺序回答；延迟期间的事件消费单独证明 | 009、010、011 |
| configuration / configuration-timing | 原生配置请求、确认或拒绝与后续执行分别记录，不推断实际生效值 | 012、013 |
| interrupt | 提交 → 原生进度屏障 → 一次中断 → 原生结果 → 关闭排空 | 016 |
| children / background-children | 实际创建、成员及父边证据驱动嵌套、并行和主任务先结束；未具备递归资源控制时受阻 | 006、007 |
| stored-children / history | 固定存储与独立发现、metadata、内容查询；查询不得启动或恢复任务 | 008、019 |
| protocol-faults / backpressure / cancellation / failure-drain / disconnect | 合成对端用屏障控制重复、unknown、慢消费、写入取消、故障与排空 | 005、014、015、017、018 |

原生进度屏障仅表示观察到了适配所定义的原生进度，不保证之后的中断或补充输入早于原生执行完成。需要精确竞态顺序时使用合成协议对端。不能用 sleep 或增大生成文本保证竞态发生。

## 执行与结果

执行方式分别为真实选定路径、仅离线和受阻。仅离线场景提供公开验收入口，不用普通文本生成替代该分支。受阻场景保留原因，启动前拒绝。两者均不产生模型请求。

流程轨迹只保存语义步骤、输入序号、必要交互和原生动作结果，不保存时间及普通 token 数量。无屏障动作、重复操作、超输入预算、交互顺序错误和无输入结果均失败。结果先于必要屏障、缺少工具或问题分别记为未触发。

用例状态与 US 覆盖情况分别报告。用例所需证据齐全时为 passed；运行错误为 failed；缺必要原生行为为 untriggered；执行条件不具备为 blocked；仅合成路径为 offline-only。范围外事项不计入本用例的 gap，也不因未覆盖整个 US 将本用例记为 partial。US 覆盖由用例与验收条件的映射管理，不由一份录制的状态推断。历史 partial 记录保留原始身份和含义。

本场景所需的身份、进度、请求关联、读取或完成记录缺失时，仍是 gap，不能移到范围外以获得通过。安全及资源限制单独说明，缩小验收范围不放宽工具权限和资源上限。取消或原生拒绝仅按指定分支验收，不自动等同成功执行。

回放同时比对用例身份与范围、缺失证据、场景哈希、语义轨迹、分支结果、原生 receipts、输入/结果/请求计数和完整 EOF；缺少任一条件不能报告通过。原始失败可按精确诊断复现，但不改写原始状态。保留没有新场景字段的历史数据的原有回放合同。

所有执行继续遵循[测试规则](../testing.md)及[代码布局](../code-layout.md)。设计或离线实现不授权真实 Agent 执行、新录制或发布。
