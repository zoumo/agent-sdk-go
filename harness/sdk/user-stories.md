# SDK 共同用户故事与验收

所有接入方使用同一套目标，不自行选择不同的必需能力集。以下是行为验收，不规定接口签名、测试框架或具体事件结构。术语与边界以[通用架构](architecture.md)为准。

## 用户故事

| 编号 | 用户目标与场景 | 共同验收 |
|---|---|---|
| SDK-US-001 | 在长期 Session 中多次提交输入并观察结果 | 一次结果不关闭 Session；后续输入沿原生规则提交，事件入口持续存续；同连接、同主身份重复拥有明确失败；不虚构通用 Turn。 |
| SDK-US-002 | 使用文本及接入范围内的结构化输入 | 保留原生内容与参数，不隐式转换为提示词；默认目标始终是主会话。 |
| SDK-US-003 | 在执行期间提交补充输入 | 不仅因前台执行而统一拒绝；沿用原生接受、拒绝和调度行为，不承诺自行排队或 steer。 |
| SDK-US-004 | 区分提交、执行结果与工具结果 | 写入或提交成功不表示完成；工具结束不表示本轮结果，执行结果不表示全部后台工作停止。 |
| SDK-US-005 | 处理原生事件、未知数据和重复消息 | 保留原生类型、未知数据与来源；不合成执行事实，不按内容相同随意去重，不宣称跨 Agent 全局顺序。 |
| SDK-US-006 | 查看直接、嵌套与并行子 Agent 输出 | 有成员证据即可交付，不要求完整父级树；原生父级和未知归属保持准确，不能混入无关事件。 |
| SDK-US-007 | 根执行先结束，继续观察后台子 Agent | 结果不关闭观察；建立必要的可用订阅，无法覆盖时报告缺口，不启动或重跑任务。 |
| SDK-US-008 | 查询 Session 中本次观察前已有的子 Agent | 使用原生查询或记录发现，不只返回缓存；保留身份与可用元数据，分页及部分覆盖可识别；不把记录当活跃状态，也不触发恢复或订阅。 |
| SDK-US-009 | 用同一操作方式接收并批准或拒绝审批 | 从事件流取得统一句柄；保留原生详情和支持的扩展；回答仅作用于对应请求，不静默降低授权语义。 |
| SDK-US-010 | 延迟审批并继续读取事件 | 等待回答不阻塞事件交付；沿用原生等待与超时，不自动决定；取消、已回答或终止后的无效句柄不能再次回答。 |
| SDK-US-011 | 回答选择题或文本题 | 仅实际原生交互请求提供回答权限；答案映射回原请求结构，普通输入和工具观察不能代替请求回答。 |
| SDK-US-012 | 选择或修改模型、思考配置 | 使用共同操作概念与原生参数；区分创建与动态修改，已知不支持时明确拒绝，不隐式映射或重建 Session。 |
| SDK-US-013 | 判断配置是否生效及影响哪些执行 | 只报告原生可确认的结果和时机；请求值不冒充实际值，不自建调度或递归修改子 Agent。 |
| SDK-US-014 | 事件消费慢于产生，同时继续控制交互 | 已接收事件完整、有序交付，控制处理不等待消费；资源限制和失败可观察，不静默丢弃。 |
| SDK-US-015 | 取消本地等待或遇到提交超时 | 等待取消不停止 Session 或执行；可能已发送时报告结果未知，不自动重发输入或回答。 |
| SDK-US-016 | 中断执行或关闭 Session | 两个动作分别表达；按原生作用范围处理，不承诺回滚或全部子 Agent 停止；只释放所拥有资源。 |
| SDK-US-017 | 遇到任务失败、连接失败或关闭后读剩余事件 | 区分原生失败与 SDK 故障；交互结束后可排空已接收事件并取得终止原因，清理不依赖消费进度。 |
| SDK-US-018 | 断线后由应用判断如何继续 | 报告错误，不自动重连；不把失联当执行停止，不保证补齐遗漏事件。 |
| SDK-US-019 | 显式 Load 后继续使用同一原生会话 | 先以原生证据确认恢复同一身份，再回放保留主历史；同入口允许历史与实时交错，标明来源和加载完成或失败；成功前禁止普通输入，保留真实回答、中断及关闭；不重执行、不产生历史回答权限。 |
| SDK-US-020 | 将 Load 回放与应用已存内容比较 | 保留可用原生关联信息和未知数据；不伪造原始实时序列，不承诺缺失数据可恢复；重复与缺失由应用判断。 |

## 能力映射

每个故事都须记录以下内容：

| 项目 | 要求 |
|---|---|
| 原生依据 | 固定版本、来源位置、相关操作或消息、适用条件。 |
| 对外表达 | 应用使用的操作、事件、错误及其成功含义。 |
| 差异与缺口 | 原生不支持、暂未实现、依赖条件、未知证据分别记录。 |
| 验证 | 对应测试或检查及实际执行结果，注明证据类型与限制。 |

共同操作的命名一致不能代替行为一致性验证。原生差异允许不同实现方式，不允许把未满足的必需故事标为完成。缺口未解决或共同合同未修订时，接入不能声称完整满足共同能力集。

## 证据与测试要求

通过 SDK 的公开交互验证完整路径，同时补充必要的编解码、故障、并发与资源边界检查。验证应包含成功、原生拒绝、取消、失联、迟到或重复交互、未知数据、慢消费及清理场景，不仅检查类型是否可解析。

源码检查、合成协议测试、真实录制回放和真实运行分别记录。合成对端须依据原生合同构造，不能只重复 SDK 自己的假设。回放通过只证明对该保留样本的处理；未执行或跳过的真实场景不能写成通过。

默认验证不执行真实 Agent 或模型，不收集新录制。需要真实验证时明确执行范围与授权，录制材料须脱敏并保留版本、来源、哈希和限制。对每项能力分别记录“是否实现”和“证据到哪一层”，不以整体测试通过替代兼容性说明。
